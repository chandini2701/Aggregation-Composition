THE FOUNDATION

One concept. Two relationships.

Both aggregation and composition represent a HAS-A relationship. The key difference is how strongly the contained object depends on the object that contains it.

CONCEPT 01

Aggregation.

A HAS-A relationship with independent objects.

What is Aggregation?

Aggregation is a special form of association in Java. One class holds a reference to an object of another class, but that object can exist independently of the containing object.

Real-world example

A Department has Teachers. If the Department is closed, a Teacher can still exist and can work in another department.

Remember

The contained object has an independent lifecycle.

Key characteristics

  • Represents a HAS-A relationship.
  • Objects can have separate lifecycles.
  • Commonly implemented using object references passed through constructors or methods.
  • Java has no special aggregation keyword.
AggregationExample.java 
class Teacher {
    String name;

    Teacher(String name) {
        this.name = name;
    }

    void display() {
        System.out.println("Teacher: " + name);
    }
}

class Department {
    Teacher teacher;

    Department(Teacher teacher) {
        this.teacher = teacher;
    }

    void show() {
        System.out.println("Department has:");
        teacher.display();
    }
}

public class AggregationExample {
    public static void main(String[] args) {
        Teacher t = new Teacher("Ravi");
        Department d = new Department(t);

        d.show();
        t.display();
    }
}
EXPECTED OUTPUT 
Department has:
Teacher: Ravi
Teacher: Ravi

CONCEPT 02

Composition.

A HAS-A relationship with strong ownership.

What is Composition?

Composition is a stronger form of association in which one object is responsible for the lifecycle of another object that forms part of it.

Real-world example

A House contains Rooms. In a typical composition model, the House creates and owns its Room objects. Those rooms are treated as parts of that particular House.

Remember

The contained object's lifecycle is tied to its owner in the modeled relationship.

Key characteristics

  • Represents strong ownership.
  • The whole controls the part's lifecycle by design.
  • Often implemented by creating the part inside the owning class.
  • Java has no special composition keyword.
CompositionExample.java 
class Room {
    void display() {
        System.out.println("Room belongs to the house.");
    }
}

class House {
    private final Room room;

    House() {
        room = new Room();
    }

    void show() {
        System.out.println("House contains:");
        room.display();
    }
}

public class CompositionExample {
    public static void main(String[] args) {
        House house = new House();
        house.show();
    }
}
EXPECTED OUTPUT 
House contains:
Room belongs to the house.

Aggregation vs Composition

Feature Aggregation Composition
Relationship Weak HAS-A Strong HAS-A
Ownership Weaker association Strong ownership
Lifecycle Objects can exist independently Part's lifecycle is tied to the whole by design

INTERVIEW TIP

How do you explain the difference?

“Aggregation and composition are both HAS-A relationships. In aggregation, the referenced object can exist independently. In composition, the owning object controls the lifecycle of its part as defined by the design.”
